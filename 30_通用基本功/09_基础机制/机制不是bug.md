# 机制不是 bug

> 结论：有明确游戏逻辑支撑的操作就是机制——前后摇、R 闪、炮车扛塔减伤都能用。

## 怎么分

| 现象 | 判定 |
| --- | --- |
| 前后摇、盲僧 R 闪、妮蔻变炮车 | 机制，设计者有意保留的规则 |
| 炮车扛塔减伤被动 | 机制，不是漏洞 |
| 程序错误导致的异常表现 | bug |

## 判断标准

能找到明确逻辑支撑的，就当机制用。别因为一个操作看起来「奇怪」就以为它不该发生，更别在实战里放弃使用。

## 例子

- 妮蔻变炮车利用炮车的扛塔减伤被动，这是战术，不是利用漏洞。
- R 闪是用闪现改变技能释放位置的合法操作，属于输入缓冲机制，见 [[技能接闪现与位移取消控制]]。
- 普攻的前后摇决定了走 A 的节奏，见 [[普攻后立刻给移动指令]]。
